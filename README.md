# DayZ Admin Tools

A small Windows desktop app (Electron) for running a DayZ Standalone dedicated server.

## System requirements

The tool itself is light (about 150–300 MB of memory, plus about 55 MB per full-resolution map). The DayZ server it runs is what needs the hardware.

| | Minimum | Recommended |
|---|---|---|
| Use | small vanilla server, up to about 20 players | 60 players, mods |
| CPU | 4 cores | 4 or more fast cores (the server's main loop runs on one thread, so clock speed matters) |
| Memory | 8 GB | 16 GB |
| Disk | SSD, 30 GB free | NVMe SSD, 50 GB free |
| Windows | Windows 10 or Server 2019, 64-bit | Windows 11 or Server 2022/2025 with Desktop Experience |
| Network | the game, query and RCon ports open (UDP 2302–2305, 27016, 2306); the website port if used (TCP 8080) | at least 20 Mbit/s upload for a full server |

Why these numbers: on a 2-core, 8 GB virtual server with a slow disk, a vanilla Chernarus start took more than 11 minutes, mostly waiting on the disk; on a modern desktop with an NVMe SSD it takes about 40 seconds. A spinning disk or Windows Defender scanning the server folder makes starts far slower (Check before start reports both and offers the Defender exclusion).

The tool installs the Windows runtimes the server needs (Visual C++ 2015-2022 x64 and DirectX June 2010) on first run. Server Core installs of Windows Server lack some desktop components DayZ uses; use the Desktop Experience edition.

## Features

- **Install & update** the DayZ server through SteamCMD (downloaded automatically on first use). Stable or Experimental branch.
- **Start / stop / restart** the server with configurable launch parameters, optional auto-restart on crash, and a live console.
- **Config Editor**: a file browser for serverDZ.cfg, BattlEye config and every XML/JSON/C file in the active mission, with syntax highlighting, search (Ctrl+F), save (Ctrl+S, keeps a `.bak`), and a **Check for errors** debugger. It validates syntax and DayZ rules: serverDZ.cfg keys, types and ranges; types.xml (nominal/min, quantmin/max, flags, categories/usages/values/tags against cfglimitsdefinition.xml, duplicates); events.xml (min/nominal/max, name prefixes, child types that exist); cfgeconomycore.xml (folders and files exist); cfgspawnabletypes.xml (items exist, chances 0..1); cfgeventspawns.xml; globals.xml; messages.xml; cfggameplay.json; init.c (brace balance, main, CreateCustomMission); BEServer_x64.cfg. **Check all files** runs everything plus server-level checks (missing mission files, mods without folders or keys).
- **Workshop mods**: browse the Steam Workshop inside the app, add a mod with one click (or paste an ID/URL), download it with SteamCMD, link it into the server folder as `@ModName`, copy `.bikey` files to `keys\`, set load order, mark server-side-only mods, check for and apply updates.
- **Logs**: list `.RPT` / `.log` / `.ADM` files from the profiles folder, follow them live, filter, and get an **error summary** that groups repeated errors by category (crash, script error, mod/PBO, network/BattlEye, mission/config, warnings) with a one-line verdict.
- **Update checks**: the tool asks Steam for the latest server build and compares every mod's workshop timestamp on a schedule (hourly by default). The Dashboard shows a notice with an "Update now" button when the server or any mod is out of date.
- **Auto update timetable**: scheduled update runs at fixed daily times or every N hours. With "only when out of date" on, a slot checks first and leaves the server running if nothing changed; otherwise it warns players (RCon), stops, installs the server and mod updates, and restarts.
- **Dependencies**: adding a mod installs everything it requires, and everything those require, all the way down, placed above it in load order. "Check updates" re-reads requirements so newly added ones are flagged, and removing or disabling a mod warns when other mods depend on it.
- **Backups**: zip backups named `backup_YYYY-MM-DD_HH-MM-SS_<label>.zip` of mpmissions, profiles, config and optionally keys. Run them manually, on a schedule, or before each scheduled restart. Keeps the newest N, and can restore one (a safety backup is taken first).
- **Scheduled restarts**: at fixed daily times (e.g. `04:00, 16:00`), every N hours of uptime, or both, with an optional backup before each restart.
- **Workshop viewer**: a built-in browser for the DayZ workshop (no API key): search, sort (trending, most subscribed, recently updated, newest, top rated), tag filters, cards with subscribers / size / last update, a details panel with the description and required items, tick-to-select with "Add selected", and pasting a collection URL adds every item in it.
- **Launch lines**: the Mods page shows the generated `-mod=` (from the enabled mods in list order), `-serverMod=` (a manual list you type, followed by mods flagged server-only), local mods, and other parameters, each with Copy. Auto-organize puts frameworks first (CF, Dabs, COT, Expansion, VPP) and then sorts by dependencies. The mod list is grouped into -mod, -serverMod and local sections; dragging between sections moves a mod. Workshop items tagged "Server" go into -serverMod automatically when installed. Every change rewrites `start_server.bat` (full command line) and `modlist.txt` in the server folder, so the server can be started without the tool.
- **Smoother mods**: adding a mod reads its "Required items" from the workshop page and offers to add the dependencies above it in load order; downloads are queued with per-mod progress; drag to reorder; Auto-sort fixes dependency order; Import found picks up mods already on disk (junctions, copied folders or local `@mods`); a banner reminds you to restart when the mod list changed while the server is running; Steam login is asked inline when needed.

### Server Management

- **Death log** (Players → Death log): one record per death built from the admin log: cause (player, infected, animal, bleeding, suicide, fall, explosion, fire, vehicle, gas, starvation, dehydration), who killed whom with what weapon at what range, the final hit's body part and damage, every hit that led up to the death, and the damage accumulated per body part. Searchable by player, killer, weapon or cause with a time range. A small **bridge script** the tool writes into the mission's `init.c` (between markers, kept current before each start, removable) records every player's gear every few seconds and at the moment of death, so each record shows the items carried; **Refund** spawns those items in pristine condition at the player's feet while they are online. **Teleport back here** sends an online player to where they died. The same bridge heals players from the Database page: everything, or just health/blood/shock, bleeding and cuts, broken bones, diseases and infections, or food and water. Discord: `/deaths`, `/death id`, `/refund`, `/heal player [what]`, `/teleport player [death_id | x z]`, and an optional channel that gets one detailed embed per death.
- **Full-resolution maps**: the map is built from the DayZ client's satellite data at its native resolution (15,360 px for Chernarus, one pixel per metre) as zoomable 512 px tiles over 6 levels, about 55 MB and 40 seconds; the Map page loads only the tiles in view and stays sharp at every zoom.
- **Map sharing** (Settings → Map sharing): a dedicated server has no game client, so link it once to a PC that has DayZ. That PC builds the map the server runs and sends it through the server's website, again by itself whenever the server switches maps (checked every 30 minutes). Uploads are HMAC-signed with the server's link key, time-stamped against replay, and checked before anything is unpacked; the key is never sent and is stored encrypted. Without a link, "Save map image…" / "Set map image…" still work.
- **Vehicles on the map** (Map → "Vehicles"): every vehicle spawn point from the mission (cfgeventspawns.xml, grouped by the Vehicle* events in events.xml with their types and nominal counts) as coloured circles, and, with the anti-dupe server mod, every vehicle on the server now as a square with its type and condition, refreshed every 5 minutes. The list shows spawn points, vehicles now and nominal per event; click one to show only it.
- **Actual loot on the map** (Map → "Actual loot now"): with the anti-dupe server mod enabled, the server writes the position of every item that is not on a player every 5 minutes. The map shows it as a heat map, or as single items when zoomed in (yellow = on the ground, blue = in containers, tents or vehicles), with a searchable list of item types and counts, a category filter and a ground-only switch.
- **Dupe detection** (Statistics → Dupe detection): two checks. The bridge script compares the engine's own item IDs across online players every few seconds, no mod needed. Optionally the tool builds and installs a **server-only mod** (`@DayZAdminTools`, loaded with -serverMod; players need nothing) that gives every item a hidden random ID saved with its persistence data, so any copy made by a relog, desync or glitch dupe carries the same ID and is reported the moment it appears, wherever it is (player, ground, container, vehicle). Detections raise the duplicate-item alert (Discord, toast, webhook) and a heavy suspicious-activity flag on the players involved. Because the mod changes what the server saves per item, enabling or disabling it needs a persistence wipe first.
- **Check before start** (Launch tab, and automatically before every launch): the install and its DLLs, every DLL the server exe imports (named exactly when missing: the Visual C++ runtime and the DirectX June 2010 runtime that provides XAPOFX1_5.dll are the usual ones on a fresh Windows, both installed automatically the first time the tool runs and again before the server starts if anything is missing, unless you untick "Install missing runtimes automatically" on the Launch tab), serverDZ.cfg and its mission folder, every -mod/-serverMod folder and its keys, the BattlEye DLL and whether the game port is already taken. Hard problems stop the launch with the reason; when the server exits before writing an RPT, the crash report explains the Windows exit code (missing runtime, broken install, crash) instead of just saying no RPT was found.
- **Router port forwarding** (Network page, and a button on the Website page): asks the router over UPnP to forward the game, query, RCon and website ports to this PC, shows what the router currently forwards, and can remove the forwards again. Routers with UPnP off need the forwards made by hand.
- **Join address on the website**: the address shown to players fills itself from your domain name (if set) or your public IP, plus the game port, and follows IP changes. Type one in the field to override it.
- **Website addresses**: the Website page lists the inward (LAN) and outward (public) IP, the website and game-server addresses built from them, each with a Copy button.
- **RCon stays connected**: a keep-alive goes out every 25 s, and there is no silence timeout: a quiet or frozen server never ends the session. After 90 s without a reply the tool quietly re-sends its login on the same connection, so the session resumes even if BattlEye had forgotten it. Only a real network error ends the connection, and then it reconnects by itself (an alert goes out only if that fails for 2 minutes); pressing Disconnect keeps it disconnected until you press Connect or the server starts again.
- **Status bar**: the top right shows Server, RCon, Bot and Web as On or Off (Server also shows Restarting and Updating). Each opens its page when clicked and explains its state on hover; RCon is amber when it should be on and is reconnecting.
- **RCon follows the server's lifecycle**: RCon is expected on once the server has finished loading, and off while it is stopped, loading, restarting on schedule or updating, so planned downtime raises no errors or alerts and the status bar says why it is off. The tool checks every 15 s and on every server change whether RCon should be on and reconnects when it should; before scheduled restart warnings are due it makes sure RCon is connected so the warnings go out.
- **Loading bar**: while the server starts, the Dashboard shows a progress bar with the current step from the server log (loading game data, Steam ready, economy starting, loading map data, persistence loaded), the percentage, the time so far and, once the tool has seen one full start on that machine, the time left. The bar is paced by that machine's own previous start, so it fills evenly on slow and fast machines alike. RCon logs in once the log says "Init sequence finished", which is when BattlEye starts answering; pressing Connect earlier explains that instead of timing out.
- **Windows Defender**: Check before start reports when Defender scans the server folder (a common cause of 10+ minute starts on servers) and offers to add the exclusion.
- **Graceful stop**: Stop and scheduled restarts send `#shutdown` over RCon when connected (otherwise a normal close request), so the server saves the world and BattlEye restores its config; the process is only forced closed if it is still running after 2 minutes (`stopGraceSec` in settings).
- **RCon that copes with slow machines**: the tool launches the server with `-BEpath` pointing at `battleye\`, so BattlEye reads exactly one config file. It connects when BattlEye is ready (port open, login answered) instead of on a fixed timer, with no time limit while the server is still loading, and the Players page says which step is failing (still loading, port not open and why, not answering, wrong password). Passwords never change while the server runs: a new one is applied at the next start, and the tool logs in with the config BattlEye actually loaded. Secrets are redacted from the audit log, and the diagnostics export includes hardware facts and the live health samples.
- **Players & RCon**: a built-in BattlEye RCon client that configures itself: before each server start the tool writes RConPassword and RConPort into `BEServer_x64.cfg` in both `profiles\BattlEye` (where BattlEye reads it when the server runs with a profiles folder) and `battleye`, and sets `BattlEye = 1` in serverDZ.cfg if it is missing (every install gets its own random 16-character password, generated once and kept; a button makes a new one on demand), keeps its own settings in step, and connects on its own once the server is up, retrying for ten minutes. Connect with the password/port from `battleye\BEServer_x64.cfg`, see online players (name, GUID, IP, ping, lobby/in-game), message, kick or ban them, broadcast to everyone, run raw RCon commands, and watch server messages live. A "Recent players" table is parsed from the admin logs (`-adminlog`) with one-click ban / whitelist / priority.
- **Bans**: manage `profiles\ban.txt` (game bans by Steam64 or DayZ ID) and `battleye\bans.txt` (GUID/IP bans with duration and reason), with names and notes kept by the tool. "loadBans via RCon" reloads BattlEye bans without a restart.
- **Whitelist** and **Priority queue**: manage `whitelist.txt` and `priority.txt` on their own pages, with a banner showing whether `enableWhitelist` is on in serverDZ.cfg.
- **Discord Bot**: a built-in bot (discord.js) you add to your own Discord server, modelled on the standalone whitelist bot. Paste a bot token, server ID and admin channel ID, start it, and it registers slash commands:
  - `/application` posts a Whitelist Application button. Applicants fill in SteamID64, character name, biography, bans and rules; the bot checks VAC/trade bans via the Steam API (optional key) and posts an embed in the admin channel with Accept / Decline / Steam Profile. Accept whitelists them (DayZ ID written to whitelist.txt with a `//SteamID64 … - DiscordID …` comment), gives the whitelist role and nicknames them after their character; Decline asks for a reason and DMs them.
  - `/ban permanent|temporary` (by Steam64 or Discord user) prompts for a reason, removes the whitelist, writes ban.txt, bans or times out the Discord account, and posts a ban notice with an Unban button. Temporary bans expire automatically. `/ban battleye`, `/ban remove`, `/ban list`, `/bantime` (players check their own ban).
  - `/whitelist`, `/priority` add/remove/list, `/search` player dossier, `/players`, `/kick`, `/say`, `/status`, `/server start|stop|restart`, `/backup`, `/help`.
  - `/mute add|remove|list`: a Discord-only mute that gives the muted role for a duration (`30m`, `2h`, `3d`, `1w`) and takes it away when the time is up.
  - **Roles**: optional whitelist, priority, banned and muted role IDs. The bot gives and removes them as people are whitelisted, put on the priority queue, banned or muted, and re-checks everyone against the list files every 5 minutes, so bans and mutes lose their role at the end of the sentence and edits made in the app or in the files are reflected in Discord.
  - Only server Administrators or configured admin roles can use admin commands. The bot's status shows online/offline and the live player count with a configurable format ("Server Online | 12/60 Players"). Optional: post every action to a log channel, and stream new ADM/RPT log lines live to a channel (batched, errors-only filter).
- **List files**: whitelist.txt, priority.txt and ban.txt store the DayZ ID (sha256 of the Steam64, base64 URL-safe) followed by a comment with the Steam64, Discord ID, name and reason, the same format the standalone bot used, so existing files keep working.
- **Website**: a public site served by the tool itself (Integrations → Website). Home page with online/offline status, player count, uptime, next restart, join address and Discord link; a mods page with workshop links; custom pages written in Markdown or raw HTML; JSON at `/api/status.json` and `/api/mods.json`. Fully customisable: files added to `<install dir>\website\` are served as-is (images, fonts, extra pages), and `template.html` (placeholders `{{site}} {{title}} {{nav}} {{content}} {{year}}`), `index.html`, `site.css`, `mods.html` or `<slug>.html` replace the generated layout, home page, stylesheet or any page. Starter files can be created from the app. **Bring your own site**: drag a folder or .zip of any static site (hand-written, or a React/Vue/Hugo/Astro build output; the tool finds the folder with index.html, including dist/build/public) onto the Website page and it is installed and served. Your site wins for every path it defines; anything else falls back to the generated pages and the API, and a `404.html` in your site is used for missing pages. Add `<script src="/dayz-status.js"></script>` and `data-dayz="online|players|max|uptime|next-restart|mods-count"` attributes (or `data-dayz-list="mods|players"` on a list) to show live server data. Forward the port on your router to publish it.
- **Domain and HTTPS** (Website page): put your own domain in front of the site. Point the domain's A record at your public IP, forward ports 80 and 443 on the router, and choose Let's Encrypt for a free certificate that the tool requests over HTTP on port 80 and renews itself 30 days before expiry, or paste your own certificate and key. HTTPS listens on 443 (configurable), plain HTTP can listen on 80, and requests for the domain over HTTP are redirected to HTTPS. Dynamic DNS keeps the A record on your current public IP through Cloudflare (API token + zone ID) or DuckDNS (token), checked every few minutes. The firewall rules and the Network page include the extra ports.
- **Restart warnings**: when RCon is connected, scheduled restarts announce themselves in-game at configurable minute marks (default 15, 5, 1) and right before the restart.

## Operations features

- **Health**: CPU, memory, server FPS (from the RPT) and player count sampled every 10 s while the server runs, kept for 24 h and drawn as sparklines on the Dashboard.
- **Alerts** (Maintenance → Alerts): every notable event (crash, crash loop, restart, backup failure, update result, low FPS, high memory, RCon lost, bot offline) can go to a Windows toast, the Discord bot's alert channel and/or a Discord webhook, with thresholds you set. A crash loop (3 unexpected exits in 10 min by default) pauses auto-restart until you start the server by hand.
- **Crash reports** (Logs → Crash reports): an unexpected exit zips the newest RPT/ADM/dump/script logs, the config and the launch line into `crashes\crash_<time>.zip` with a JSON summary and the log analyser's verdict; post it to Discord with one click.
- **Steam ban checks**: with a Steam Web API key set on the Discord Bot page, every Steam64 the tool knows (lists, applications, player database) is checked for VAC, game, trade and community bans and profile privacy, once a day and on demand ("Check Steam bans" on the Database page, `/maintenance` in Discord). Results show as badges on the Database, Bans, Whitelist and Priority pages and on the application embeds, which are refreshed like the old bot's maintenance pass. A player who picks up a new ban raises a "Steam ban" alert.
- **Account check** (Database page): alt-account signals per player: Steam account age, level, game count, profile privacy and whether DayZ is in the library (from the Steam API), every IP they connected from (recorded from RCon while they play), other players who used the same IP, and a BattleMetrics search link. The signals add up to a score; a player at or above 4 is flagged in the table, sortable with "Suspicious first", and a "Flagged player joined" alert fires when one connects. Shared IPs can be a household or carrier NAT, so it is a lead, not proof. "Check Steam bans" refreshes the account facts too.
- **Discord role check**: the Database page shows which of the configured whitelist / priority / banned / muted roles each linked Discord member holds, and flags mismatches with the list files.
- **Player database** (Players → Database): every player seen in the admin logs with name history, first/last seen, sessions and playtime, kills/deaths, last position and notes, joined with the whitelist/ban lists and Discord applications. Search, sort, quick ban/whitelist/priority/mute. `/search` in the bot shows playtime, last seen and K/D.
- **Economy: brush and item picker**: on the Types tab pick a tier, usage, tag or category in the Brush bar, then left-click rows to add it and right-click to remove it (Esc clears the brush). On the Spawnable types tab, press "Add from list" on a cargo or attachments group and click items in the searchable list on the right, filtered by class (weapons, food, clothes, tools…); open entries stay open while you edit.
- **Wipes**: full wipe, world wipe (bases, vehicles and loot are reset but players.db is kept so characters survive) and character wipe, each behind an arming checkbox that disarms itself after 60 seconds plus a typed confirmation, with a backup first. All three are also available as scheduled task types.
- **Economy: import and custom files**: "Import…" merges entries into the open file from pasted XML (a whole file or just the `<type>` / `<event>` blocks from a mod's readme) or a picked file; dropping an .xml file anywhere on the Economy page does the same. Existing entries can be replaced or kept. "New file…" creates a custom types / events / spawnable types file in a sub folder of the active mission and registers it in cfgeconomycore.xml so the server loads it (comments and layout in that file are kept). All three tabs read the active mission named in serverDZ.cfg plus every file it registers.
- **Economy editor** (Server → Economy): table editors for `types.xml` (vanilla and CE-registered custom files), `events.xml` and `cfgspawnabletypes.xml`. Filter by name/category/usage/tier/tag, edit numbers inline, pick flags from `cfglimitsdefinition.xml`, select rows and bulk set/multiply/add values or add/remove flags, then Save (keeps a `.bak`, validates, lists problems). Files are written in the exact layout the server expects.
- **Settings**: keep running in the tray with start/stop/restart/backup from the tray menu, start minimised, launch at Windows login, export/import settings, and self-update from GitHub Releases (set `build.publish` in package.json to your repo and publish with `npm run release`, which needs a `GH_TOKEN`).

## More operations features

- **Auto-start**: Settings → "Start the DayZ server automatically when the tool starts", with a delay. Combined with "Launch when Windows starts" and auto-restart on crash, a rebooted machine comes back on its own.
- **Mission** (Server → Mission): list missions in `mpmissions\`, switch the active one (updates serverDZ.cfg), full wipe or characters-only wipe with a backup first and a typed confirmation, and a form editor for `cfggameplay.json`.
- **Tasks** (Maintenance → Tasks): scheduled in-game messages, RCon commands, backups, updates, restarts, start/stop, or any command line, at daily times or on an interval.
- **Network** (Maintenance → Network): the ports the server uses and whether something is listening, your public IP, and one-click Windows firewall rules (asks for admin rights).
- **Off-site backups** (Backups page): after each backup, copy it to another folder (OneDrive, NAS…) and/or upload by FTP/FTPS, with remote retention.
- **Server keys** (Installed page): every .bikey in the keys folder with its signer and the mods that ship it, including @folders the tool does not manage. Each mod row lists its keys and marks shared ones. Removing a mod deletes its keys unless another mod in the server or download folder ships a key of the same name (the removal dialog says which keys go and which stay); an update that changes a mod's key removes the old one the same way. Leftover keys from mods that are gone, missing or outdated copies, and two mods shipping different keys under one file name are flagged, with Remove and Fix buttons. dayz.bikey is never touched.
- **Check mods** (Installed page): duplicate PBOs across mods, missing or uncopied keys, unlinked folders, verifySignatures, plus a ready-to-paste "players need these mods" list with workshop links.
- **Instances** (Server → Instances): run several servers on one PC, each fully separate. A new instance gets its own folder (`<root>\<name>\server` for the game files, mission and keys, `steamcmd` with its own Workshop mods, `tool` for its settings, logs, death log, players and statistics, `backups`), copied from an existing instance in about half a minute (server files and mission without the world, optionally the mods and keys, the world and the tool settings) or installed fresh from its own window. Ports are picked automatically: the next free block (game port +100, Steam query +100, RCon +100, website +1), checked against the other instances and against what is already listening, and written to its serverDZ.cfg; Check before start reports any clash and offers Move to free ports. Each background instance runs as its own process of the app and keeps running (restarts, RCon, backups, bot, website) when the main window is closed; the main window starts them with it, lists them all with status, players, CPU, memory, FPS and ports, starts, stops, restarts, updates and backs up any of them, opens each in its own window (also from the instance switcher in the top bar and the tray), and has Update all for game updates. Firewall rules and router port mappings are named per instance, so instances never remove each other's. Maps are built once and shared. Passwords and tokens are never copied; a new instance can take over the main window's Steam login, kept encrypted in its own folder.
- **CPU cores** (Launch page): the tool reads the processor (cores and hyper-threads) and each instance chooses Windows decides, Auto (the cores are split between every instance set to Auto, keeping core 0 for Windows and the tools on 4+ cores) or exactly the cores ticked, plus a process priority. The server is pinned right after it starts (no administrator rights needed) and -cpuCount follows the core count. Check before start warns when more servers run than the cores and memory carry (about 2 cores and 4-6 GB each) or when two instances are pinned to the same cores.
- **Shared or separate Discord bot** (per instance): Own bot (its own token), Shared with the main instance, or Off. A shared instance posts its alerts, feeds, death log and live logs through the main bot, labelled with its name, into the main bot's channels unless it sets its own; the main bot's server commands (/status, /players, /kick, /say, /server, /backup, /deaths, /death, /refund, /heal, /teleport, /search) get a server option that runs the command on that instance, /status without one shows every server, whitelist, priority and bans made through the bot apply to every server sharing it, and the bot's status shows the servers online and the total players. Sharing is the default for new instances, and each shared server gets its own kill feed, join feed and death log: the main bot creates #<name>-kill-feed, #<name>-joins and #<name>-death-log next to its own feed channels (or reuses them) when the instance is created, or later with the button on that instance's Discord Bot page. The bot's invite link now includes Manage Channels, which these channels and support tickets need; a bot invited earlier needs re-inviting or that permission on its role.
- **The server outlives the tool**: it runs in its own process group with its console output in `profiles\server-console.log`, and the tool remembers it, so after an app update, a crash of the tool or closing a background instance's tool, the tool takes the running server over again (RCon, pinning, crash handling) instead of losing it or starting a second copy.
- **Remote admin panel**: enable `/admin` on the Website page with a password to start, stop, restart, back up, broadcast and kick from a phone.
- **Map** (Players → Map): the map and world size are detected from the active mission template (Chernarus, Livonia, Sakhal, Namalsk, Deer Isle and others) and the map image is built automatically from the game's own satellite tiles: the tool reads `worlds_<map>_data.pbo` from the DayZ client install found through Steam (or from a map mod's addons), decodes the PAA tiles and stitches them into `<install dir>\maps\<map>.png` in a few seconds. Player positions from the admin log are drawn as dots with names, green for online, and refresh every 5 seconds while the page is open. You can still drop in your own image with "Set map image". **Overlays**: a travel heatmap of where players go, a death heatmap, and a deaths-by-cause view with coloured dots and a legend (players, infected, animals, vehicles, explosions, falls, bleeding, environment), all built from the admin log, with a rebuild from every log on disk and an opacity slider.
- **Server settings form** (Server → Launch): every serverDZ.cfg key the tool knows, the common ones (name, passwords, max players, whitelist, signatures, voice, third person, time and acceleration, MOTD, logging) as a form. Values are written in place, so comments and the rest of the file are untouched; a `.bak` is kept.
- **Launch flags** as checkboxes: -dologs, -adminlog, -netlog, -freezecheck and -limitFPS. The FPS graph needs -dologs; the player database, map and Discord feeds need -adminlog.
- **Remembered Steam password** (Installation page, opt-in): stored encrypted with your Windows account (Electron safeStorage) so scheduled mod updates keep working after the tool restarts. A "Steam Guard code needed" alert fires if SteamCMD asks for a code.
- **Backup before updates**: the update timetable takes a backup before installing (on by default). Backups can also include the tool's own data (settings, player database, Discord applications and bans, Steam ban results).
- **Log cleanup** (Logs page): when the server stops (or with Clean now), delete logs older than N days. **What to clean** chooses each kind on its own (RPT, ADM, script, error, crash logs and dumps, other .log files) and every log folder in the profiles folder, including those mods create (EventManagerLog, WebApiLog, ExpansionMod/Logs and the like, found automatically two levels deep, or added by path), each with its own file pattern and age, and shows how many files each would delete now. Folders whose name contains "log" are cleaned by default; other mod folders only when ticked. The newest file of each row is always kept, and patterns that could match settings or saves (*, .json, .xml, .cfg) and the folders holding this tool's data, BattlEye and player storage are never touched.
- **Server browser check** (Network page): a Steam A2S query against localhost and your public IP shows whether the server is visible from the internet, with the name, map and player count it reports.
- **Scheduled wipes** (Tasks): "Full wipe" and "Character wipe" task types warn players, stop the server, back up, wipe and start again.
- **Tickets** (Discord): `/ticketpanel` posts an "Open a ticket" button; each ticket gets a private channel under the configured category, visible to the opener, the admin roles and the bot. Close it with the button or `/ticket close`; a transcript is posted to the ticket log channel and the channel is deleted. `/ticket add` brings someone else in, `/ticket list` shows open ones.
- **Kill feed and join feed** (Discord): kills, deaths, joins and leaves parsed live from the admin log are posted to channels you pick, batched every few seconds.
- **Web admin password** is stored as a salted hash.
- **Running unattended**: "Launch when Windows starts" needs a logged-in Windows session, so on a dedicated box enable automatic login for the account that runs the tool (or run the tool from a scheduled task "at log on") and keep it in the tray. The tool itself is not a Windows service.
- **Map navigation**: scroll to zoom, drag to pan, double-click to reset, click a player dot for their details (with a jump to the Database), Shift+click two points to measure a distance; the cursor's world coordinates are shown.
- **More heatmaps**: besides travel and deaths, combat hits, base building, logout spots and login / spawn spots, each with a time range (24 h, 7 days, 30 days, all).
- **Loot spawn locations**: pick an item and the map shows every building where it can spawn, computed the way the central economy decides: building positions from mapgrouppos.xml, each building's containers and their usage / category / tag flags from mapgroupproto.xml, the item's flags from the types files and the tier regions from areaflags.map. Dot size is the number of matching loot points; the summary lists the most common building types. Click a dot for the building and its coordinates.
- **Statistics** (Players → Statistics): today / 7 days / 30 days tiles for deaths by cause, player kills, unique and new players, peak online, average FPS, uptime, restarts and crashes; charts for deaths per hour and per day, peak and unique players per day and FPS per day; leaderboards for kills, deaths, K/D, playtime, longest sessions and weapons. A daily summary can be posted to a Discord channel at a set time (Discord Bot page), posted now, or copied.
- **Combat statistics** (Statistics page and each player's detail): from the admin log's hit and kill lines: damage dealt and taken per player, hits, headshots, kills per weapon, longest and average kill distance, a weapons table (kills, hits, damage, headshots, average and longest range, ammo), body parts hit, rivalries (who kills whom most), favourite weapons and base-building actions. "Rebuild from all logs" re-reads every admin log on disk.
- **Accuracy and suspicious activity**: the admin log records hits but not shots fired, so true shots-to-hits accuracy is not available in vanilla; the tool records what the log supports per player: hits per kill, headshot percentage, the percentage split of body parts hit and average hit distance. Suspicious-activity flags are raised from combat patterns: headshot rate over 55% after 25 hits, headshots at 400 m or more, four or more hits on two or more players within 1.5 s, three or more kills within 10 s, kills at 900 m or more, and movement faster than 80 m/s between logged positions. Each flag adds to a score shown on the Database page, in the player's details and on a Suspicious activity table on the Statistics page; a score of 3 or more raises an alert. Three more rules cover the common cheats that are not aim-related: **rapid relogs** (four or more logins within ten minutes, the pattern relog duping needs), **combat logging** (logging out within 20 s of being hit by a player) and **BattlEye kicks** (Script Restriction, Game Restriction, Corrupted Memory, Global or Admin Ban lines from the server log, weighted highest). Every flag is kept with its time, so the Suspicious activity table can be viewed for the last 24 hours, 7 days, 30 days or all time, each player's details show flag counts per window and the last events, and BattlEye kicks also land in the audit log. Thresholds can be tuned in settings.json under `combatFlags`. These are leads for a replay or a closer look, never proof.
- **Diagnostics** (Settings): "Open tool.log" reveals the tool's own log, and "Export diagnostics bundle" zips tool.log, the audit log, statistics, system info, a credential-free copy of the settings, the newest crash reports and the tail of the latest RPT, ready to share when reporting a problem.
- **Audit log** (Maintenance → Audit log): every state-changing action in the app (server start/stop, list changes, wipes, config and economy saves, backups, RCon commands, tasks, mod changes, settings), every Discord bot command with the user who ran it, and every web admin panel action with its IP, searchable and exportable to CSV.
- **Themes and shortcuts**: dark or light theme in Settings; Ctrl+1…9 jump to pages, F5 refreshes the page, Ctrl+K goes to a page by name.

## Security notes

- The window runs with context isolation, no Node integration and a sandboxed renderer; the page can only call the IPC handlers the tool defines, the renderer's script policy is self-only, and navigation or pop-ups to other sites are blocked (links open in your browser).
- Secrets in settings.json (Discord bot token, Steam API key, RCon password, FTP password, webhook URL, DNS token, HTTPS private key) are stored encrypted with Windows DPAPI through Electron's safeStorage, bound to your Windows account, as is the remembered Steam password. Settings export never includes them.
- The public website serves files only from the website folder (path traversal is rejected), sends nosniff / frame-deny / no-referrer headers, and the /admin panel uses a salted-hash password with constant-time comparison, a 15-minute lock-out after five failed logins, HttpOnly SameSite=Strict cookies (Secure over HTTPS) and an origin check on every state-changing request. Logins and admin actions go to the audit log.
- Shell commands are run with argument arrays, not strings; the only free-form command execution is the "command line" task type, which you write yourself.
- The Discord bot checks Administrator permission or your admin role IDs on every admin command; applicants and ticket openers can only act on their own records.
- **Other web software check** (Network page): looks for PHP installs (XAMPP, WAMP, Laragon, plain PHP, IIS) on the machine, reads their PHP version, compares it with the releases that fix the October 2026 "php2shell" remote code execution bugs (CISA alert, CVE-2026-109618 / CVE-2026-109619), and shows whether any of it is running. If a vulnerable PHP is running when the game server starts, an alert is raised. The tool itself contains no PHP.
- Known dependency advisory: node-forge (pulled in by the Let's Encrypt client) has an advisory about RSA signature verification. The tool only uses it to generate keys and certificate requests locally and never verifies signatures with it, so the affected code path is not reachable.

## Notes

- **Releasing a new version**: `release.bat` (or the same steps by hand) must publish `dist/latest.yml` and the `.blockmap` together with the two exes; the in-app updater reads `latest.yml` from the latest GitHub release and reports a 404 without it. The updater works in the installed app; the portable exe can check but installs by hand.
- **Startup speed**: the portable exe unpacks itself (about 85 MB) into a temp folder on every launch, which costs several seconds, and running it from a OneDrive folder adds more. Use the installer (`DayZ-Server-Tool-Setup-<version>.exe`) for day-to-day use: it starts in a second or two and updates itself in place. The tool's own initialisation takes well under a second; the rest is Electron starting.

- The server app installs with an anonymous Steam login. Workshop mods require a Steam account that owns DayZ; enter it on the Install page. The password is kept in memory only.
- Mods are stored under `<install dir>\steamcmd\steamapps\workshop\content\221100\<id>` and linked into `<install dir>\server\@Name` with a directory junction, so no files are duplicated.
- Settings live in `%APPDATA%\dayz-server-tool\settings.json`.
- Open the server port (default 2302 UDP, plus 27016 UDP for Steam query) in the Windows firewall and router.

Diagnostics

                
The tool writes its own log (console lines, failed actions, errors) to tool.log in the data folder. The bundle zips that log, the audit log, statistics, a scrubbed copy of the settings, system info, the newest crash reports and the tail of the latest server RPT, so it can be shared for debugging without exposing credentials.

Server Wipe

                
Every wipe needs the server stopped, takes a backup first, and asks you to type WIPE. Restoring that backup is the only way back.

                
                

                  
Full wipe
Everything in storage_1: characters, bases, vehicles and loot state. A fresh start.

                  
World wipe
Bases, vehicles and loot are reset. Characters are kept (players.db stays).

                  
Character wipe
Only players.db is deleted, so everyone respawns fresh while bases and vehicles stay.

Dupe detection two live items with one ID means a copy was madechecking…

            
Two checks run. The bridge script compares the engine's own item IDs across online players every few seconds (no mod needed). The server-only mod goes further: every item gets a hidden random ID saved with it, so any copy made by a relog, desync or glitch dupe carries the same ID and is reported the moment it appears, wherever it is. Players need nothing installed.

            
Before enabling the mod: it changes what the server saves for each item, so the first start with it on (and the first start after turning it off) needs a persistence wipe from the Mission page, or existing items load with warnings.

Portal (/portal)

                
A sign-in for your staff: moderators, admins, game masters and developers each see only what their group or their own permissions allow (players and the live map, in-game admin actions, deaths, tickets, logs, server control). Users and groups are managed inside the portal by anyone with the "Manage portal users" permission; everything they do is logged under their name.

Show live server data in your site
                  
Add <script src="/dayz-status.js"></script> to your page, then put data-dayz="…" on any element: online, players, max, uptime, next-restart, restart-times, mods-count. Use data-dayz-list="mods" or "players" on a <ul> for lists. It refreshes every 30 seconds, and raw JSON is at /api/status.json.

                

              

              

                
Custom files

                
Anything in this folder is served by the site: images, fonts, extra HTML pages. Reference them as /name.ext. Special files take over parts of the site:

                
    
                  
  • template.html replaces the layout. Placeholders: {{site}}, {{title}}, {{nav}}, {{content}}, {{year}}.
    • 
                  
  • index.html replaces the home page entirely. Live data is at /api/status.json and /api/mods.json.
    • 
                  
  • site.css replaces the generated stylesheet; mods.html or <slug>.html replace a single page.
